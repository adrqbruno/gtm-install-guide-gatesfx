01

Why one container on both properties

One container across the website and the CRM lets AdRoq measure the full journey in one place: ad click → site visit → registration → KYC → first deposit (FTD).

Without the CRM install, every ad platform stops seeing users at the moment they register. Google Ads, Performance Max and Meta then optimise toward clicks and sign-ups instead of funded traders, and cost per deposit cannot be reported.

Once the snippet is live, AdRoq manages every tag (GA4, Google Ads, Meta, programmatic pixels) inside GTM. The Gates development team installs the code once and pushes the agreed dataLayer events; no further code changes are needed to add or change marketing tags.

02

How it works, in one minute

GTM is a single loader script. The page tells GTM what happened; GTM decides which marketing tags to fire.

1. The containerA small script (the snippet) loads GTM on the page. It is the only marketing code that has to live in the site's source.
2. The dataLayerA shared list on the page. The CRM adds a message to it whenever something important happens, such as first_deposit.
3. The tagsInside GTM, AdRoq maps each message to GA4, Google Ads, Meta and programmatic tags, respecting the user's consent.

The container and its two snippets

The same two snippets go on every page of the website and the CRM. Copy them exactly as below; do not change the container ID or the variable names.

Where each snippet goes on the page

Snippet 1 · paste as high in the <head> as possible

Ideally right after <meta charset>, before any other script.

head · snippet 1
<!-- Google Tag Manager -->
<script>(function(w,d,s,l,i){w[l]=w[l]||[];w[l].push({'gtm.start':
new Date().getTime(),event:'gtm.js'});var f=d.getElementsByTagName(s)[0],
j=d.createElement(s),dl=l!='dataLayer'?'&l='+l:'';j.async=true;j.src=
'https://www.googletagmanager.com/gtm.js?id='+i+dl;f.parentNode.insertBefore(j,f);
})(window,document,'script','dataLayer','GTM-KBW53BVD');</script>
<!-- End Google Tag Manager -->

Snippet 2 · paste immediately after the opening <body> tag

body · snippet 2
<!-- Google Tag Manager (noscript) -->
<noscript><iframe src="https://www.googletagmanager.com/ns.html?id=GTM-KBW53BVD"
height="0" width="0" style="display:none;visibility:hidden"></iframe></noscript>
<!-- End Google Tag Manager (noscript) -->
i

If the page also pushes dataLayer values on load (for example consent defaults or user status), those dataLayer.push calls must sit above Snippet 1.

04

Website installation

Add both snippets to the global template so they load on every page, including landing pages, blog, legal pages and every language version. Never paste them page by page.

PlatformWhere to install
Custom code / frameworkMain layout file (e.g. _document, layout.html, header.php): Snippet 1 in <head>, Snippet 2 after <body>
WordPressTheme header.php (child theme) or a header/footer plugin with separate head and body slots. Do not use a GTM plugin that injects its own container.
WebflowProject Settings → Custom Code: Snippet 1 in Head Code; Snippet 2 in Footer Code (Webflow has no body-start slot, and this is acceptable for the noscript fallback).
Unbounce / other landing page buildersGlobal script manager, placement "Head" and "Body Top", applied to all domains.
Next.js / React SPALoad the snippet once in the root layout; push a page_view event to the dataLayer on every route change (see section 06).

05

CRM / client area installation

The CRM is where the money events happen, so it gets the same container (GTM-KBW53BVD), never a second one. Install both snippets in the CRM's master layout so they load on public and logged-in pages alike.

Pages that must carry the snippets

CRM pageWhy it matters
Registration / sign-upFires sign_up, the first conversion every channel optimises on
LoginIdentifies returning users for retargeting exclusions
KYC / verification stepsFires kyc_start and kyc_complete; shows where users drop off
Deposit / funding page and its confirmationFires deposit and first_deposit, the main optimisation event
Dashboard / trading account pagesActive-trader and retention audiences
i

If the CRM is a third-party platform (for example a white-label broker CRM), check whether it has a custom header / tracking scripts field in its admin. If it does not, the CRM vendor must add the snippets; send them this guide.

Rule 1 · Fire conversions only after the server confirms

Fire conversion events only after the server confirms the action (account created, KYC approved, deposit credited), not on button click.

Rule 2 · Payment provider pages are out of scope

Payment provider pages (card forms, 3-D Secure, e-wallet redirects) are hosted by the PSP. Do not try to install GTM there; fire deposit when the user returns to the CRM confirmation page or from the backend (see section 06).

06

Cross-domain tracking and dataLayer events

The website and CRM must be read as one session. AdRoq configures cross-domain linking in GTM; the Gates team only needs to confirm the domains and keep URL parameters intact.

The events the CRM team pushes

Event names and fields are fixed; AdRoq builds all tags on top of them.

EventWhen to pushRequired fields
page_viewEvery route change (single-page apps only)page_path, page_title
sign_upAccount created, confirmed by serveruser_id, method
loginSuccessful loginuser_id
kyc_startFirst KYC step openeduser_id
kyc_completeKYC approved (or submitted, if approval is delayed; tell AdRoq which)user_id, kyc_status
depositEvery deposit crediteduser_id, transaction_id, value, currency, payment_method
first_depositFirst credited deposit only (FTD)user_id, transaction_id, value, currency

Example push for a first deposit

javascript · CRM confirmation page
window.dataLayer = window.dataLayer || [];
window.dataLayer.push({
  event: 'first_deposit',
  user_id: 'GFX-102938',        // internal CRM ID, never email or name
  transaction_id: 'DEP-55021', // unique, prevents duplicate conversions
  value: 250.00,
  currency: 'USD',
  payment_method: 'card'
});
i

For Enhanced Conversions and Meta CAPI, AdRoq also needs the user's email and phone at sign_up and first_deposit. These are hashed (SHA-256) before leaving the browser or sent server-side; the exact method is agreed with the Gates team before go-live.

i

Where deposits are confirmed asynchronously by the PSP, a backend postback (server-side event) is more reliable than a browser push. AdRoq will spec this separately if needed.

07

Consent and privacy

Consent Mode v2 must be live before marketing tags fire, on both the website and the CRM. Google requires it for EEA/UK traffic, and Google Ads audiences and conversion modelling depend on it.

  • The cookie banner (CMP) must load on every page of both properties and share one consent state across domains.
  • Preferred setup: a Google-certified CMP (e.g. Cookiebot, OneTrust, CookieYes) deployed through GTM by AdRoq. If Gates already runs a CMP hard-coded on the site, tell AdRoq which one.
  • If consent defaults are set in code, the gtag('consent','default', …) call goes above Snippet 1.
!

Never put personal data in the dataLayer in plain text: no names, email addresses, phone numbers, ID document numbers or card details. Use the internal CRM user_id only; hashing of email and phone for ad platforms is handled as described in section 06.

08

How to check the installation

The Gates team can confirm the base install in five minutes; AdRoq then validates events end to end in GTM Preview before publishing any tag.

  1. View the page sourceOpen the page in Chrome, right-click → View Page Source, search for GTM-KBW53BVD.
    You should seeIt appears twice: once in <head>, once after <body>.
  2. Check the network requestOpen DevTools → Network, filter by gtm.js.
    You should seeA request with id=GTM-KBW53BVD returning status 200.
  3. Inspect the dataLayerIn the DevTools Console, type dataLayer and press Enter.
    You should seeAn array that includes gtm.js.
  4. Connect Tag AssistantGo to tagassistant.google.com, connect the site URL. Repeat for the CRM URL.
    You should seeThe container is found on both properties.
  5. Walk the full journey on stagingWith a test account: website → registration → KYC → test deposit.
    You should seeEach event from section 06 appears once in Tag Assistant, with the right fields.
  6. Rule out duplicatesCheck the snippet loads only once per page.
    You should seeOne container, one copy. Two containers or two copies cause duplicate data.
i

The "Test your website" field in GTM's install dialog only confirms that the code exists on one URL; it is not a full check.

09

Who does what, and next steps

Gates installs and sends events; AdRoq configures, tests and publishes. Nothing goes live in GTM without AdRoq.

TaskOwner
Install snippets on website (all pages, locales, landing domains)Gates web team
Install snippets on CRM / client areaGates CRM team or CRM vendor
Push dataLayer events (section 06)Gates CRM team
Confirm domains, CMP and existing hard-coded pixelsGates team
GTM configuration: GA4, Google Ads, Enhanced Conversions, Meta Pixel + CAPI, programmatic tags, cross-domain, Consent ModeAdRoq
End-to-end QA and publishingAdRoq, with a Gates test account

Do

  • Install one container, in the global template, on both properties.
  • Send new pixel requests to AdRoq to deploy in GTM.
  • Grant AdRoq Publish access and keep at least one Gates admin on the account.

Don't

  • Add a second GTM container or a GTM plugin alongside this one.
  • Hard-code new marketing pixels.
  • Publish or edit the GTM container without AdRoq.

Glossary

GTM container
The single Google Tag Manager workspace (GTM-KBW53BVD) that holds every marketing tag for GatesFX.
Snippet
The two pieces of code that load the container on a page: a script in the head and a noscript fallback in the body.
dataLayer
A list on the page where the site or CRM writes what just happened, so GTM can react to it.
Event
A named message in the dataLayer, such as sign_up or first_deposit, with its fields.
FTD
First-time deposit: a user's first credited deposit. The main conversion campaigns optimise toward.
KYC
Know Your Customer: the identity verification steps a user completes before trading.
Cross-domain tracking
Keeping one session as a user moves from the website to the CRM, using the _gl parameter.
Consent Mode v2
Google's standard for passing the user's cookie choice to tags. Required for EEA/UK traffic.
CMP
Consent management platform: the cookie banner and the tool that stores the user's choice.
Enhanced Conversions
Google Ads feature that matches conversions to ad clicks using hashed email or phone.
Meta CAPI
Meta Conversions API: sends events from the server to Meta, alongside the browser Pixel.
PSP
Payment service provider: the company that hosts the card or e-wallet payment pages.
Postback
A server-to-server message that confirms an event, such as a credited deposit, without relying on the browser.
transaction_id
A unique ID per deposit. Platforms use it to ignore duplicates of the same conversion.
